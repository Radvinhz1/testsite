# testsite — آکادمی برنامه‌نویسی با Django

نسخهٔ اول سایت آموزشی فارسی، راست‌به‌چپ و مناسب موبایل. ورود با ایمیل، عکس پروفایل، دو دوره Python و C#، مراحل قفل‌شده، بررسی دستی تکلیف و گواهی اختصاصی.

## قابلیت‌های آماده

- ثبت‌نام، ورود، خروج و بازیابی رمز با ایمیل.
- انتخاب یک یا هر دو دوره و افزودن دوره دوم از **Add a New Course**.
- چهار مرحله برای هر دوره با محتوای آموزشی و تکلیف نمونه قابل جایگزینی پیش از ثبت‌نام دانشجو.
- ارسال متن کد یا فایل؛ سابقه تلاش‌ها و بازخورد مدرس.
- قبولی با نمره **بالاتر از ۷۰**؛ نمره ۷۰ قبول نیست.
- بررسی توسط ادمین، تاریخچه اصلاح نمره و جلوگیری از ثبت هم‌زمان نتایج متناقض.
- قفل واقعی سمت سرور، پیشرفت مستقل دوره‌ها و حفظ سوابق در تغییر نمره.
- گواهی PDF با بارگذاری ادمین؛ تا آماده‌شدن فایل، متن وضعیت نمایش داده می‌شود.
- فایل‌های خصوصی بدون URL عمومی؛ کنترل مالکیت برای دانلود.
- Migrationهای دیتابیس، داده‌های نمونه و تست‌های عملکرد/مجوز/هم‌زمانی.

تصحیح کد **دستی** است؛ برنامهٔ دانشجو اجرا نمی‌شود. محتوای دوره‌ها نمونه آموزشی اولیه است، نه دوره جامع. پرداخت و میزبانی اینترنتی در این نسخه راه‌اندازی نشده‌اند.

## اجرای سریع روی ویندوز — بدون نیاز اولیه به MySQL

برای دیدن سایت فوراً می‌توان از SQLite استفاده کرد. تنظیم اصلی پروژه MySQL است؛ روش اتصال آن در بخش بعد آمده است. Python 3.13 پیشنهاد می‌شود.

در PowerShell:

```powershell
git clone git@github.com:Radvinhz1/testsite.git
cd testsite
py -3.13 -m venv .venv
.\.venv\Scripts\python.exe -m pip install -r requirements.txt
Copy-Item .env.example .env
```

فایل `.env` را باز کنید و این دو مقدار را قرار دهید:

```dotenv
DJANGO_DEBUG=true
DB_ENGINE=sqlite
```

سپس:

```powershell
.\.venv\Scripts\python.exe manage.py migrate
.\.venv\Scripts\python.exe manage.py seed_courses
.\.venv\Scripts\python.exe manage.py createsuperuser
.\.venv\Scripts\python.exe manage.py runserver
```

این روش نیازمند فعال‌کردن محیط مجازی یا تغییر Execution Policy نیست. اگر مخزن را از قبل دارید، در پوشهٔ همان مخزن ابتدا `git pull origin main` بزنید.

- سایت: http://127.0.0.1:8000/
- مدیریت: http://127.0.0.1:8000/admin/
- بررسی تکالیف: http://127.0.0.1:8000/staff/reviews/

در `createsuperuser` ایمیل و رمز مدیر را خودتان تعیین می‌کنید. هیچ رمز پیش‌فرض مدیریتی در پروژه نیست. برای تجربه دانشجو، از صفحه ثبت‌نام یک حساب جدا بسازید. در حالت محلی، لینک بازیابی رمز در ترمینال چاپ می‌شود؛ برای ارسال واقعی ایمیل، SMTP تنظیم شود.

## استفاده از MySQL

MySQL 8.4 و موتور InnoDB پیشنهاد می‌شود. روی Windows x64 با Python 3.13:

```powershell
.\.venv\Scripts\python.exe -m pip install -r requirements-mysql.txt
```

در MySQL Workbench فایل [docs/mysql.sql](docs/mysql.sql) را اجرا و یک کاربر اختصاصی برای دیتابیس بسازید. در `.env`:

```dotenv
DB_ENGINE=mysql
DB_NAME=testsite
DB_USER=testsite
DB_PASSWORD=رمز_واقعی_که_خودتان_تعیین_کرده‌اید
DB_HOST=127.0.0.1
DB_PORT=3306
```

سپس دستورهای `migrate`، `seed_courses` و `createsuperuser` را دوباره برای دیتابیس MySQL اجرا کنید. تغییر از SQLite به MySQL **داده‌های قبلی را منتقل نمی‌کند**؛ دو دیتابیس مستقل هستند. فایل `.env` در Git نادیده گرفته می‌شود.

برای Linux پیش از نصب mysqlclient، بسته‌های `python3-dev default-libmysqlclient-dev build-essential pkg-config` لازم‌اند. اگر نصب mysqlclient روی ویندوز تلاش کرد از سورس کامپایل کند، معماری ۶۴بیتی و Python 3.13 را بررسی کنید؛ نصب پایه برای پیش‌نمایش SQLite به این درایور نیاز ندارد.

## ادمین چگونه کار می‌کند؟

۱. با حساب مدیر وارد `/admin/` شوید.
۲. بخش **Submissions** یا منوی «بررسی تکالیف» را باز کنید.
۳. پاسخ دانشجو، معیار نمره‌دهی و پاسخ مرجع خصوصی را ببینید.
۴. نمره و بازخورد را ثبت کنید. برای تغییر نمره قبلی، علت تغییر لازم است.
۵. پس از تکمیل همه مراحل، در **Enrollments** یا **Certificates** روی «بارگذاری گواهی» بزنید و PDF همان دانشجو را بارگذاری کنید.

ادمین می‌تواند صورت سؤال و پاسخ مرجع را در **Assignments** و متن درس را در **Stages**، قبل از ثبت‌نام نخستین دانشجو تغییر دهد. برای دوره دارای دانشجو، یک **CourseVersion** جدید به حالت draft بسازید، مراحل و تکالیف آن را اضافه کنید و بعد status را published کنید. نسخه‌های قبلی و پیشرفت دانشجویان حفظ می‌شوند.

عنوان و توضیح عمومی دوره قابل ویرایش است. تغییر ساختار نسخه دارای دانشجو از پنل مدیریت ممنوع است. حذف اطلاعات آموزشی از پنل عمداً غیرفعال است؛ دوره را غیرفعال یا نسخه را archived کنید.

برای مدیر محدود، `is_staff` به تنهایی کافی نیست. مجوز `learning.review_submission` برای بررسی و `learning.change_certificate` برای صدور گواهی لازم است. برای نمایش فهرست‌ها در پنل نیز مجوز view مدل‌های مربوط را بدهید. مدیریت حساب‌ها و اعطای نقش فقط برای superuser قابل تغییر است.

## فایل‌ها و حدود آپلود

- عکس: JPEG/PNG/WebP، حداکثر ۲ MB؛ پس از اعتبارسنجی به JPEG حداکثر ۸۰۰ پیکسل تبدیل می‌شود.
- پاسخ کد: py/cs/txt، متن UTF-8، حداکثر ۱ MB.
- گواهی: PDF معتبر بدون رمز، حداکثر ۵ MB.
- فایل درس/مرجع: PDF حداکثر ۵ MB یا متن/کد حداکثر ۱ MB.
- همه فایل‌ها در `private_media/` ذخیره می‌شوند؛ این پوشه را در وب‌سرور عمومی نکنید.

این محدودیت فایل‌های درس از سقف پیشنهادی اولیه کمتر انتخاب شده است. PDFها به‌صورت attachment دانلود می‌شوند؛ اعتبارسنجی فرمت به معنای اسکن ضدویروس نیست.

## ساختار کد

| مسیر | مسئولیت |
|---|---|
| `config/` | تنظیمات محیط، URLها و WSGI |
| `accounts/` | کاربر سفارشی، پروفایل، ورود و محدودیت درخواست |
| `learning/models.py` | دوره، نسخه، مرحله، تکلیف، ثبت‌نام، نمره و گواهی |
| `learning/services.py` | قواعد ثبت‌نام، قفل مراحل، تصحیح و صدور گواهی در تراکنش |
| `learning/views.py` | صفحه‌های دانشجو و مدرس و دانلود مجاز |
| `learning/admin.py` | پنل مدیریت محتوا و لینک عملیات مدرس |
| `templates/` و `static/` | رابط فارسی و CSS واکنش‌گرا |
| `*/migrations/` | ساخت و تغییر جداول دیتابیس |
| `learning/tests.py` | تست جریان‌ها، مرزها و مجوزها |

برای ساده نگه‌داشتن نسخه اول، ماژول‌های پیشنهادی دوره/تکلیف/گواهی در یک app به نام `learning` قرار گرفته‌اند. منطق‌های حساس در سرویس‌های مشترک‌اند و مسیرهای وب آن‌ها را دور نمی‌زنند. فیلد تصویر جلد دوره فعلاً به نشان‌های گرافیکی Python و C# تبدیل شده است.

## تست

```powershell
.\.venv\Scripts\python.exe manage.py test --settings=config.test_settings
.\.venv\Scripts\python.exe manage.py makemigrations --check --dry-run
```

با SQLite سه تست هم‌زمانی عمداً اجرا نمی‌شوند؛ برای بررسی قفل ردیف‌ها، همان فرمان تست را با MySQL اجرا کنید. کاربر دیتابیس تست باید اجازه ساخت و حذف `test_testsite` داشته باشد؛ این مجوز فقط برای محیط تست لازم است.

GitHub Actions دو job جدا برای SQLite و MySQL 8.4 دارد. در MySQL، ثبت‌نام هم‌زمان، پاسخ هم‌زمان و تصحیح هم‌زمان نیز بررسی می‌شوند. فایل [docs/VALIDATION.md](docs/VALIDATION.md) نتیجه اعتبارسنجی نسخه تحویلی را توضیح می‌دهد.
