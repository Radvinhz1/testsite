# دیتابیس اجرایی

منبع حقیقت ساختار دیتابیس، مدل‌ها و Migrationهای ثبت‌شده است. SQL Server انتخاب اصلی و SQLite فقط گزینه پیش‌نمایش است.

| جدول | نقش | قید اصلی |
|---|---|---|
| accounts_user | کاربر و هش رمز | ایمیل lowercase یکتا |
| accounts_profile | تصویر و معرفی | یک پروفایل برای کاربر |
| accounts_ratelimitbucket | شمارنده محدودیت درخواست | کلید هش یکتا و زمان انقضا |
| learning_course | مشخصات عمومی دوره | slug یکتا |
| learning_courseversion | نسخه و سیاست قبولی | دوره + شماره نسخه یکتا |
| learning_stage | درس و ترتیب مرحله | نسخه + ترتیب یکتا |
| learning_assignment | تکلیف و پاسخ مرجع | یک تکلیف برای مرحله |
| learning_enrollment | ثبت‌نام و نسخه ثابت | کاربر + دوره یکتا |
| learning_submission | پاسخ و شماره تلاش | ثبت‌نام + تکلیف + تلاش یکتا |
| learning_graderevision | تاریخچه نمره | پاسخ + بازبینی یکتا؛ نمره ۰ تا ۱۰۰ |
| learning_certificate | گواهی خصوصی | یک گواهی برای ثبت‌نام؛ UUID یکتا |
| learning_auditevent | سابقه عملیات نمره و گواهی | زمان و انجام‌دهنده |

جدول‌های مجوزها، session و log مدیریت را Django ایجاد می‌کند. تصاویر و PDFها داخل جدول نیستند؛ مسیرشان ذخیره می‌شود. زمان‌ها در UTC و نمایش در تهران است.

برای دیدن SQL واقعی روی دیتابیس انتخاب‌شده:

```text
python manage.py sqlmigrate accounts 0001
python manage.py sqlmigrate learning 0001
python manage.py sqlmigrate learning 0002
```

برای اعمال:

```text
python manage.py migrate
```

پس از تغییر عمدی مدل‌ها، `makemigrations` تولید و در Git ثبت شود. SQL را به‌صورت دستی در کنار Migration برای همان جدول‌ها اجرا نکنید.

## قواعد مهم

- ثبت‌نام روی ردیف کاربر و نسخه دوره قفل می‌گیرد؛ عضویت دوباره، همان رکورد موجود را برمی‌گرداند.
- ارسال، نمره‌دهی و صدور گواهی روی Enrollment با select_for_update قفل می‌گیرند.
- بررسی هم‌زمان با شماره بازبینی مورد انتظار کنترل می‌شود؛ فرم قدیمی نتیجه جدید را بازنویسی نمی‌کند.
- نمره معتبر هر پاسخ آخرین بازبینی آن است. حداقل یک پاسخ قبول‌شده برای قبولی مرحله کافی است.
- درصد پیشرفت از مراحل قبول‌شده متوالی از ابتدا محاسبه می‌شود؛ در ستون مستقل ذخیره نمی‌شود.
- بازپس‌گیری قبولی، سابقه را حفظ اما مرحله‌های بعد و دانلود گواهی را مسدود می‌کند. صدور دوباره گواهی باید صریح انجام شود.
- تغییر ساختار نسخه دارای دانشجو در فرم مدیریت ممنوع و با قفل همان نسخه در برابر ثبت‌نام هم‌زمان محافظت می‌شود.
- ORM خام و دستکاری مستقیم SQL ابزار مدیریت روزمره نیست؛ برای عملیات دامنه از learning/services.py استفاده کنید.
- حساب کاربری عمومی نمی‌تواند نقش یا مجوز خودش را تغییر دهد.

رابط کاربری تعلیق ثبت‌نام در نسخه اول ارائه نشده است؛ وضعیت suspended در مدل و منطق دسترسی پشتیبانی می‌شود. غیرفعال‌کردن حساب از پنل مدیر دسترسی آن حساب را قطع می‌کند.

## سیاست نهایی و سازگاری SQL Server

- اتصال از backend مایکروسافت `mssql-django` و `pyodbc` با ODBC Driver 18 (یا 17 با تنظیم صریح) استفاده می‌کند.
- نمره ۷۰ قبول است. پیش‌فرض `passing_operator=ge` و `passing_threshold=70` است؛ تصحیح دستی توسط ادمین انجام می‌شود.
- Migration شماره 0002 این سیاست را روی تمام نسخه‌های موجود اعمال و وضعیت تکمیل را اصلاح می‌کند. از مدل‌های تاریخی استفاده می‌کند و به سرویس‌های متغیر آینده وابسته نیست. پاسخ‌ها و تاریخچه نمرات حفظ می‌شوند.
- برگرداندن خودکار این اصلاح داده ممکن نیست؛ قبل از اجرای آن روی داده واقعی، پشتیبان لازم است.
- SQLite و SQL Server دیتابیس‌های مستقل‌اند؛ تغییر متغیر اتصال داده‌ها را جابه‌جا نمی‌کند.
- متن فارسی با نوع‌های Unicode مانند NVARCHAR ذخیره می‌شود؛ JSON در SQL Server از ستون متنی با بررسی JSON معتبر استفاده می‌کند.
- اجرای تست‌های هم‌زمانی با backend `microsoft` اجباری است؛ SQLite جایگزین تست قفل‌گذاری نیست.

منبع تنظیمات backend: https://github.com/microsoft/mssql-django
